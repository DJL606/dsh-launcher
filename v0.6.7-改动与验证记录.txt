一、本轮四项需求的落实
----------------------
1) 合并托盘退出按钮
   · 旧：\"停止服务并退出\"（只管自己的服务） + \"结束 3080 服务并退出…\"（只管别人的）
   · 新：一个 \"停止服务并退出\" → ExitWithServiceHandling()
       自己有服务 → 直接停；自己没有而 3080 有服务 → 问一次\"结束它并退出？\"；
       都没有 → 直接退出。问答只保留在这一处。

2) 启动检查 dsh 更新 + 插件更新，并给勾选菜单
   · StartupStartupUpdateCheck()：启动后约 12 秒后台检查（等 UI 消息循环就绪再弹）
   · 托盘 \"检查 dsh / 插件更新…\" 走同一套收集与界面
   · 菜单 = CheckedListBox，每项可单独勾选（默认全选），显示\"当前 → 可用\"
   · dsh 本体更新 → 既有后台下载（失败自动回退）
   · 插件更新 → 文件级：npm pack → tar 解包 → 覆盖（先整目录备份）→ 同步 package.json

   ★ 安全闸门（本轮自己发现并修掉的坑）：
     只提示与当前 dsh 相容的插件版本。依据 npm 上该版本的 engines.dsh 与
     peerDependencies 里所有 @deepseek-ai/dsh-* 约束（简版 semver 判定，
     支持 >=A <B、^A、~A、A、||）。实测 dsh-perm-gate 4.2.1 要求
     >=0.1.7-rc.1 <0.1.8-0，本机 0.1.5-rc.3 → 被正确拦下（否则一升就崩）。
   · 自动跳过：link:/file:/workspace: 规格、node_modules 里是符号链接/junction 的插件

3) 检查 bug（本轮实修 / 实证）
   · 修：启动环境净化 —— 命令行清 NODE_OPTIONS + CODEBUDDY_SAFE_DELETE_BULK_GUARD。
     实测根因：dsh 写配置时删自己的 .lock，WorkBuddy 注入的 node 语言 shim 的
     safe-delete 守卫会拦下它 → dsh 报
     `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] ... .credentials.yaml.lock`
     直接启动失败；清掉即恢复。另：上次异常退出残留的 .lock 会让 dsh 卡在
     \"timed out waiting for the writer lock\"，删掉即可。
   · 加守卫：勾选菜单只在 UI 消息循环就绪后显示（uiLoopRunning 判定 + 最多等 20 秒），
     避免在 MTA 后台线程上开窗。
   · 加自检：client-api 通路自检（token→cookie→POST 只读接口），失败留日志 + 气泡。
   · 复核过但非 bug：日志里重复的\"可安装性校验\"来自多次启动/自检，不是循环调用。

     与本机 0.1.5-rc.3 不兼容 → 无可用更新版本 → 删除。
     已删：profile 配置引用（昨天已做）+ 今天删掉 node_modules 里的残留目录。

     engines.dsh = >=0.1.5-rc.1 <0.1.6-0，无加载期版本断言 → 不会重演混版崩溃）。
     安装方式：文件级（npm pack 解包到 profile node_modules + 只装运行时依赖 chokidar@5
     + 注册 package.json/dependencies/bundles），不依赖 pnpm。
